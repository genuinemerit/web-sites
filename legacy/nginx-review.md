# nginx configuration review

Reviewed 2026-09-29: full `nginx.conf` plus every vhost in
`sites-available/`. Stock Ubuntu nginx 1.26.0 package, no custom modules
(`modules-enabled/` is empty), no config management tool — everything here
was hand-edited directly on the box, consistent with what David described.

## `nginx.conf` (global)

- Standard Ubuntu default, with two intentional tweaks vs. the package's
  own `.bak` copy it left behind: `worker_connections` raised
  768 → 1024, and `error_log` level set to `notice` (from the default,
  unleveled). Both reasonable, minor tuning — not concerning.
- `server_tokens build;` — leaks nginx version/build tag. The file's own
  stock comment says to turn this off; it hasn't been. See
  `certificates.md` for the same note in TLS context.
- No global security headers set anywhere (`X-Content-Type-Options`,
  `X-Frame-Options`/`frame-ancestors`, `Referrer-Policy`, CSP) — absent
  across every vhost, not just missing from one. Worth adding as a
  baseline on the new droplet rather than per-site.
- `gzip on;` with all the tuning directives commented out (using nginx's
  built-in defaults for comp level etc.) — fine, not wrong, just noting
  it's using defaults rather than deliberate tuning.

## Per-vhost patterns

**`music`, `openmic`, `qigong`, `taiji`** — near-identical, clearly
generated by the same original template and then each auto-edited by
Certbot's nginx plugin independently over time:

- Each has **duplicate `root` directives** — one inside `location /`
  (the real one) and redundant `root /usr/share/nginx/html;` lines left
  over elsewhere in the block (visible in the earlier `grep` pass) —
  harmless since the innermost/most-specific wins in nginx, but untidy.
- Each has a **Certbot-injected `if ($host = ...)` redirect block** for the
  HTTP→HTTPS redirect. This is Certbot's standard auto-edit behavior, not
  a mistake — but `if` inside `server` blocks for anything beyond a couple
  of well-known safe patterns is a known nginx anti-pattern ("if is evil")
  because of how it interacts with the request-processing phases. Certbot's
  specific pattern here is one of the few considered safe, so this isn't
  urgent — just noting it as the "curious to a trained eye, actually fine"
  category you asked about.
- Each has the **original, pre-Certbot port-80 block left behind, commented
  out**, right above Certbot's own replacement block. Dead, harmless
  clutter — safe to drop when these get rebuilt.
- Formatting is inconsistent between them (indentation, blank lines) —
  cosmetic, they were clearly not written in one sitting.

**`sfp`** stands apart — visibly hand-crafted with more care, and later
than the others (uses `http2 on;` as its own directive rather than the
older `listen 443 ssl http2;` form, has explanatory comments, no leftover
duplicate `root` lines, uses `try_files` instead of relying on bare
`location /`). Two things worth flagging here specifically:

- The CORS block for `/saskan/assets/`:

  ```nginx
  add_header Access-Control-Allow-Origin "*" always;
  add_header Vary "Origin" always;
  ```

  This is internally inconsistent: `Vary: Origin` tells caches "the
  response differs by request Origin," which only makes sense if
  `Access-Control-Allow-Origin` *reflects* the requesting origin back.
  Here it's a hardcoded wildcard `*` — the response is identical
  regardless of Origin, so `Vary: Origin` is meaningless (not wrong/unsafe,
  just pointless — a copy-paste from a more typical reflected-origin CORS
  setup that doesn't apply to a static wildcard). Moot now anyway: the
  `/saskan/assets/` content this block served was deleted 2026-09-30 (see
  `content-inventory.md`/`decisions.md`) — this `location` block in
  `sfp.conf` is dead config that can be dropped whenever `sfp` gets
  rebuilt.
- The cache-control regex trick
  (`if ($uri ~ "\.[0-9a-f]{6,}\.")` inside a `location` block) is another
  instance of the same "`if` inside `location`" pattern flagged above —
  functionally fine for this narrow case, just worth knowing if this
  pattern gets carried forward intentionally rather than by habit.

## `sites-available/default`

Untouched stock Ubuntu placeholder (`server_name _;`, `root
/var/www/html`) — catches any request that doesn't match a real
`server_name`, including (since the `mint` DNS record removal) anything
that still resolves to this droplet's IP without a matching vhost. Fine as
a catch-all; nothing to change.
